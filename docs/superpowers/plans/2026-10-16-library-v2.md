# Member Library v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the beta-only, admin-authored library into the place CODErs go to write their next module: the Google Sheet's content mirrored into R2, member uploads and writing with drafts, collaborative lists, popularity and reading time, moderation, and optional smart search.

**Architecture:**
- **Pure rules** live in `src/lib/library/` and are unit-tested in the Workers pool: block model, taxonomy, activity math, and the tracker state machine.
- **Data** lives in four repositories registered in `src/db/repositories/index.ts`: `library` (items, comments, moderation, reports), `libraryTags`, `libraryLists` and `libraryActivity`. One access module, `library-access.ts`, decides who sees and edits what. Every query applies those rules in SQL.
- **UI:** server pages under `/portal/library`, with small client components for the editor, the Save picker and the reading tracker.
- **Smart search** is a separate server module behind its own flag. It falls back silently to SQL search.
- **Seed import and redaction** are local scripts that read and write only `.local/library-import/`.

**Tech Stack:**
- Next.js 16.2 on OpenNext/Cloudflare Workers, React 19
- D1 + Drizzle 0.45, Zod 4
- R2 (`BUCKET`), Workers AI (`AI`), Vectorize (`VECTORIZE`)
- Vitest Workers pool, Playwright
- Ghostscript and PyMuPDF for local redaction only

**Spec:** `docs/superpowers/specs/2026-10-16-library-v2-design.md` (commit `322a221`). Read it alongside this plan. Section numbers below (§) refer to it.

## Global Constraints

- **The repository is PUBLIC.** Never commit anything from the sheet or `.local/library-import/`: titles, names, files, manifest, seed SQL, review logs. Test fixtures are synthetic only (§15.1).
- **Commits never carry `Co-Authored-By` or any AI trailer.**
- **Every `wrangler` command that touches remote D1, R2, Vectorize, or deploys:** show CJ the exact command and wait for approval (project CLAUDE.md).
- **Tests run in the Workers vitest pool:** `.ts` files only, no jsdom, no React render tests, no `better-sqlite3` import. Put UI logic in pure `.ts` modules and test those.
- **Content rendering:** stored blocks render through our own JSX. Never `dangerouslySetInnerHTML`. Links must start with `https://` or `mailto:`.
- **Limits:**
  - Upload caps: `library_file` 50 MB (PDF, DOCX, PPTX, XLSX); `library_image` 10 MB (GIF, JPEG, PNG, WebP). Existing purposes keep 5 MB.
  - Activity: ping every 15 s of active time, idle after 60 s with no interaction, at most 30 s credited per ping, at most 7,200 s (2 h) per member per item per day. The day is the UTC+8 calendar day.
  - Popularity display: hide "Saved by N" when N < 3. Related shelf: up to 6 items.
  - Smart search: at most 5 keyword chips plus at most 3 free keywords; AI time budget about 1.5 s, then silent fallback. Never generate sentences, and never show "AI", sparkles, or a chatbot.
  - Blocks: at most 300 per page.
- **Mobile:** user-controlled labels (titles, tag names, list names, author names) get `min-w-0` + `break-all` (`break-words` doesn't work here).
- **Workspace:** work in a worktree `.worktrees/library-v2` on branch `feat/library-v2` off `beta`.
  - The event-feedback feature runs in parallel in `.worktrees/event-feedback`. It owns migration `0012` and adds the `AI` binding.
  - **Task 4 (migration) must not start until event feedback's `0012` is committed on `beta` and merged into `feat/library-v2`.** The event-feedback session messages the library session with the commit hash.
- **Graphify:** run `graphify query` before reading raw source. Before any `graphify update .`, confirm `.local/` stays out of `graphify-out/` (Task 0).

## Review Focus

1. **Hidden items leaking through side doors.**
   - Input: drafts, pending, taken-down and confidential items.
   - Must stay hidden from: search, Related, collections, list views (placeholder only), save counts, `most saved`, the hours total, and R2 file URLs.
   - Pinned by tests in Tasks 5, 7, 8 and 10.
2. **Inflated reading time.**
   - Input: two tabs open on the same item, a laptop left open, or a script spamming pings.
   - Expected: the server still credits at most 30 s per ping and 2 h per member, item and day.
   - Pinned in Task 8 (two-tab test) and Task 3 (tracker idles out).
3. **Spoofed uploads.**
   - Input: a `.exe` renamed `.pdf` with `Content-Type: application/pdf`, or a 60 MB PDF.
   - Expected: 415 or 413. Check the PDF magic bytes `%PDF-` and the ZIP header `PK\x03\x04` for Office files.
   - Pinned in Task 10.
4. **Smart search garbage.**
   - Input: AI timeout, AI returns prose instead of JSON, or Vectorize returns IDs of confidential or deleted items.
   - Expected: plain results with no chips, and nothing hidden leaks.
   - Pinned in Task 17.
5. **Shared list races.**
   - Input: two editors reorder at once, or an editor reorders with an ID that isn't in the list.
   - Expected: last write wins, positions stay a dense `0..n-1`, unknown IDs are ignored.
   - Pinned in Task 7.

**Interfaces:**
- Produces (`activity.ts`):
  ```ts
  export const ACTIVITY = { pingIntervalMs: 15_000, idleMs: 60_000, maxPingSeconds: 30, dailyCapSeconds: 7_200 } as const;
  export function utc8Day(at: Date): string;                           // "YYYY-MM-DD" in UTC+8
  export function creditSeconds(requested: number, alreadyToday: number): number; // clamp to [0,30] then to remaining cap; non-finite → 0
  export function formatHours(totalSeconds: number): string;            // <3600 → "Less than an hour"; else "1,204 hours" (floor, en-US grouping; 1 → "1 hour")
  export function showSaveCount(saves: number): boolean;               // saves >= 3
  ```
- Produces (`activity-tracker.ts`), a DOM-free state machine:
  ```ts
  export type TrackerEvent = { type: "interact" | "visible" | "hidden" | "tick"; at: number };
  export function createReadingTracker(): { feed(event: TrackerEvent): number }; // returns whole seconds to send now (0 = nothing)
  ```
  The tracker counts time only while visible and within `idleMs` of the last interaction. It returns the accumulated seconds once they reach ≥ 15. On `hidden` it flushes whatever has accumulated (≥ 1 s).
